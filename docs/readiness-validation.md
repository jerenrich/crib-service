## Optional overnight silent crying alarms — 25 October 2026

Parent Settings → Overnight wrist alarms → Silent Watch alarms is off by default and stays enabled until switched off. Apply additive migration `0011_silent_watch_alarms.sql` before deploying this Worker. No existing notification setting is replaced. The Listener's current event API remains compatible.

The dispatch claim reads the optional flag and phone token in its existing destination query. For an opted-in real event, ordinary Watch delivery runs independently from a separate soundless, user-visible Parent notification carrying `content-available: 1` and `silentCryAlarm: true`. The auxiliary attempt has its own receipt and never changes the ordinary event's result, target or retry state. Worker/DO background lifetime retains auxiliary work without holding the original receipt or reminder schedule. When the original destination is already the phone, its existing notification receives the marker and background-execution request instead of sending a duplicate. Tests and disabled settings never enable this route.

The Parent checks both local opt-in and current server opt-in, paired status, episode relevance, request freshness and local/server snooze state before scheduling a silent-tone alarm three seconds later. An active episode uses one alarm UUID, so repeated notifications do not restart it. An App Intent on the system Stop button stops local crying alarms and submits the existing acknowledgement, using the configured snooze duration. A failed network acknowledgement remains queued across relaunch and is retried on later Parent activity. Native Watch notification acknowledgements preserve real/test classification across relaunch so real Snooze can also stop the alarm locally without muting real crying for a test acknowledgement. Turning the option off cancels this app's real-cry alarms locally even if the setting cannot yet sync to the server. Role, backend and pairing changes disable the local feature. Stale status requests cannot turn off a newer opt-in or cancel a newer alarm.

The Parent must be locked for the Watch routing observed in the earlier trial; wear the Watch unlocked, with Silent Mode and Prominent haptics. No Watch app session needs to stay open. Existing notifications remain the fallback if the Parent is suspended, force-quit, offline, denied alarm permission, or cannot schedule an alarm. Automatic quiet cleanup requires the Parent to obtain a fresh status snapshot; users can always Stop the system alarm. The earlier supervised silent test proved one locked-phone trial, not overnight reliability for this integrated real-cry feature.

Validation covers independent Watch delivery with a failed or stalled auxiliary phone send, phone-only routing without a duplicate notification, absent phone tokens, default-off and Parent-only configuration, exclusion of tests and acknowledged events, payload age and relevance, snooze suppression and durable real/test acknowledgement classification.
